# Startup Discovery — MAX Hackathon MVP

Startup Discovery — чат-бот внутри MAX для поиска и установления делового контакта между стартапами и людьми, которые ищут проекты для инвестиций, пилотов, партнёрства или присоединения к команде.

> От стартап-питча до делового контакта — внутри MAX.

## 🔗 Бот в MAX

https://max.ru/t558_hakaton_max_bot

## 🎯 Проблема

Основатели стартапов и люди, заинтересованные в новых проектах, часто находятся в разных сообществах, чатах и каналах.

Поиск подходящего проекта требует ручного просмотра большого количества информации, а после обнаружения интересного стартапа необходимо отдельно искать способ связаться с основателем.

Startup Discovery объединяет поиск проекта и первый деловой контакт внутри MAX.

## 💡 Решение

Пользователь задаёт критерии интересующих его стартапов.

Бот:

1. сохраняет опубликованные стартапы;
2. принимает критерии поиска;
3. находит соответствующие проекты;
4. показывает структурированную карточку стартапа;
5. позволяет нажать «🤝 Интересно»;
6. помогает сформировать конкретное предложение;
7. отправляет предложение основателю через MAX;
8. позволяет основателю принять или отклонить предложение.

## 👥 Целевая аудитория

### Кто ищет стартапы

- частные инвесторы;
- инвестиционные клубы;
- предприниматели;
- компании, ищущие проекты для пилота;
- потенциальные партнёры;
- специалисты, желающие присоединиться к команде.

### Основатели стартапов

Основатели, которые ищут:

- инвестиции;
- пилотных клиентов;
- партнёров;
- команду или сооснователя.

## 🚀 Основной пользовательский сценарий

### 1. Основатель публикует стартап

`/start` → `🚀 Разместить стартап`

Бот последовательно запрашивает:

- название;
- категорию;
- рынок B2B / B2C / B2B2C;
- стадию;
- проблему;
- решение;
- traction;
- что ищет стартап;
- сумму инвестиций, если необходимы инвестиции.

После предварительного просмотра основатель публикует проект.

### 2. Пользователь ищет стартап

`/start` → `🔎 Найти стартап`

Пользователь задаёт:

- цель поиска;
- категорию;
- минимальную стадию;
- максимальный размер инвестиций — для инвестиционного сценария.

### 3. Matching

MVP использует детерминированный matching.

Проверяются критерии:

- категория;
- стадия;
- цель;
- инвестиционный бюджет, если применимо.

Бот показывает количество совпавших критериев, например:

`4/4 критерия`

MVP не использует искусственные AI-проценты совместимости.

### 4. Отправка предложения

В карточке подходящего проекта пользователь нажимает:

`🤝 Интересно`

Затем выбирает тип предложения и вводит сообщение.

После подтверждения предложение сохраняется и отправляется основателю стартапа непосредственно в MAX.

### 5. Ответ основателя

Основатель получает предложение и может:

- принять его;
- отклонить его.

Отправитель получает уведомление о решении.

Таким образом, основной end-to-end сценарий полностью проходит внутри MAX:

**публикация → поиск → matching → интерес → предложение → решение основателя**

## 🐳 Запуск через Docker

### Требования

Необходимо установить:

- Docker;
- Docker Compose.

### 1. Клонировать репозиторий

```bash
git clone https://github.com/ymyradowic-bit/startup-discovery-max.git
cd startup-discovery-max
```

### 2. Создать `.env`

Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Linux/macOS:

```bash
cp .env.example .env
```

После этого добавить токен:

```env
BOT_TOKEN=YOUR_MAX_BOT_TOKEN
```

### 3. Запустить

```bash
docker compose up --build
```

После запуска бот подключается к MAX.

Отдельный входящий HTTP-порт для основного сценария MVP не требуется.

```bash
docker compose down
```

## 💾 Хранение данных

SQLite используется для хранения:

- пользователей;
- стартапов;
- поисковых профилей;
- предложений.

База хранится в:

```text
./data/startup_discovery.db
```

В Docker используется bind mount:

```text
./data:/app/data
```

Поэтому данные сохраняются после остановки и повторного запуска контейнера.

При первом запуске база создаётся автоматически.

## 🧪 Как проверить MVP

1. Запустить бота.
2. Отправить `/start`.
3. Нажать `🚀 Разместить стартап`.
4. Заполнить карточку стартапа.
5. Опубликовать стартап.
6. Вернуться в главное меню.
7. Нажать `🔎 Найти стартап`.
8. Задать критерии, соответствующие созданному проекту.
9. Получить карточку проекта.
10. Нажать `🤝 Интересно`.
11. Выбрать тип предложения.
12. Написать сообщение.
13. Подтвердить отправку.
14. Основатель получает предложение в MAX.
15. Основатель принимает или отклоняет предложение.
16. Отправитель получает уведомление о решении.

Для демонстрационного тестирования MVP допускает проверку сценария созданного проекта с одного аккаунта.

## 🔐 TLS

Для корректного HTTPS-соединения с MAX API внутри Debian-based Docker image в проект добавлен публичный сертификат:

```text
russian_trusted_root_ca.crt
```

Docker устанавливает сертификат в системное хранилище CA.

Также контейнер использует:

```text
NODE_EXTRA_CA_CERTS=/usr/local/share/ca-certificates/russian_trusted_root_ca.crt
```

Это позволяет выполнять TLS-проверку сертификата MAX API без отключения проверки HTTPS.

## 🔒 Безопасность

Секретный `BOT_TOKEN`:

- хранится только в `.env`;
- `.env` находится в `.gitignore`;
- `.env` исключён из Docker build context через `.dockerignore`;
- токен не хранится в исходном коде.

В репозитории находится только безопасный шаблон:

```text
.env.example
```

## ⚠️ Ограничения MVP

Текущая версия сфокусирована на одном end-to-end сценарии.

В MVP:

- matching основан на заданных критериях, а не на ML/LLM;
- используется SQLite;
- выбирается одна основная категория поиска;
- нет отдельного web-интерфейса;
- нет собственного внешнего API;
- бот предназначен прежде всего для проверки основной продуктовой гипотезы и пользовательского сценария.

## 📌 MVP

Главная проверяемая гипотеза:

**Можно ли сократить путь от поиска подходящего стартапа до конкретного делового предложения, проведя весь основной сценарий внутри MAX?**

Startup Discovery реализует этот путь:

**Founder → Startup → Discovery → Match → Interest → Offer → Founder decision**
