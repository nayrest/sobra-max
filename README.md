# SOBRA — поиск партнёра под бизнес-идею в MAX

SOBRA — мини-приложение и бот в мессенджере MAX. Оно помогает начинающему предпринимателю понять, что в его идее уже проверено, а что нет, и найти человека, у которого есть недостающие компетенции: партнёра или co-founder'а.

SOBRA не оценивает, хорошая ли идея. Она показывает, что нужно проверить, фиксирует прогресс и помогает найти человека с недостающими компетенциями.

## Назначение

**Проблема.** Человек с бизнес-идеей обычно не знает, что в ней уже подтверждено, а что пока только предположение. Партнёра он ищет по знакомым и в чатах, объясняет каждому идею заново и не может коротко сформулировать, какие навыки ему нужны.

**Решение.** SOBRA проводит основателя по циклу из пяти шагов:

| Шаг | Что происходит |
|---|---|
| 1. **Idea Check** | Основатель отвечает на вопросы: клиент, проблема, решение, конкуренты, спрос, бизнес-модель, экономика, какой партнёр нужен |
| 2. **Project Map** | ИИ раскладывает ответы по 7 блокам: ✓ подтверждено фактами, ~ гипотеза, ✗ не проработано. Считается готовность проекта в процентах |
| 3. **Action Plan** | По каждому неподтверждённому блоку появляется задача («Провести интервью», «Проверить спрос»…) с методикой; ИИ может расписать её под конкретный проект |
| 4. **Update** | Основатель возвращается с результатом, карта пересчитывается: блок меняется с ✗ на ✓, готовность растёт. Если фактов мало, по блоку появляется следующий шаг |
| 5. **AI Match** | ИИ сравнивает потребность проекта с опытом кандидатов по смыслу и объясняет: почему подходит, чего не хватает, что уточнить |

Кандидат заполняет профиль, ищет проекты (ИИ объясняет, насколько он подходит) и откликается. Когда основатель принимает отклик, случается **MATCH**: стороны видят телефон и e-mail друг друга. Контакты показываются только при согласии пользователя.

**Целевая аудитория:**
- основатели на ранней стадии (от идеи до первых продаж), которым нужен co-founder или партнёр;
- специалисты, которые хотят войти в команду или стать партнёром в проекте.

## Основной пользовательский сценарий

**Основатель**
1. Открывает бота в MAX и запускает мини-приложение.
2. Заполняет профиль: ФИО, e-mail, телефон, цель, «о себе» и согласие на показ контактов после MATCH. Фото по желанию.
3. «Проекты» → «Проверить новую идею» → отвечает на вопросы и получает карту проекта.
4. В «Следующих шагах» выбирает задачу, выполняет её и нажимает «Внести результат». Карта пересчитывается.
5. «Опубликовать» → «Подобрать партнёра»: ИИ показывает кандидатов с объяснением → «Пригласить в проект».
6. «Отклики» → «Принять» → MATCH, контакт кандидата во вкладке «Контакты».

**Кандидат**
1. Заполняет профиль и отмечает «Показывать мой профиль основателям».
2. «Поиск» → выбирает цель и сферу → ИИ оценивает каждый проект относительно профиля.
3. «Откликнуться» → пишет сообщение основателю.
4. Бот присылает уведомление о решении. После MATCH контакты основателя появляются во вкладке «Контакты».

Бот в чате только знакомит с сервисом (`/start`) и присылает уведомления: новый отклик, приглашение, MATCH, отказ. Вся работа идёт в мини-приложении.

## Состав и архитектура

```text
 Пользователь в MAX
   │  чат с ботом                         мини-приложение (WebView)
   ▼                                        │  HTTPS, Authorization: Bearer <initData>
 MAX Bot API ◄──── long polling ────┐       ▼
                                    │   Nginx (HTTPS, Let's Encrypt)
                                    │     ├── /       → frontend/ (статика)
                                    │     └── /api/   → 127.0.0.1:3000
                                    │                    │
                         ┌──────────┴────────────────────▼──────────┐
                         │ контейнер startup-discovery (Node.js 24) │
                         │  index.js       — бот: /start, уведомления│
                         │  api.js         — REST API (Express 5)    │
                         │  idea-check.js  — карта проекта           │
                         │  action-plan.js — план действий, Update   │
                         │  ai-matching.js — AI Match (YandexGPT)    │
                         │  db.js          — доступ к PostgreSQL     │
                         └──────────┬───────────────────┬───────────┘
                                    ▼                   ▼
                          контейнер postgres      YandexGPT API
                          (PostgreSQL 17)         (Yandex Cloud)
```

| Компонент | Где | Назначение |
|---|---|---|
| `backend/` | контейнер `startup-discovery` | Бот и REST API в одном процессе Node.js |
| `frontend/` | Nginx на сервере / контейнер `web` локально | Мини-приложение: HTML, CSS, JavaScript без сборки |
| PostgreSQL 17 | контейнер `postgres` | Пользователи, проекты, карты, задачи, профили, отклики, фото |
| YandexGPT | внешний сервис | Карта проекта, методика задач, AI Match |

**Авторизация.** Мини-приложение передаёт `initData` от MAX Bridge. Сервер проверяет подпись по алгоритму MAX: HMAC-SHA256, ключ получается из токена бота. Срок действия подписи — 24 часа. Имя и id пользователя берутся только из подписанных данных, подделать их нельзя. Для автоматической проверки есть отдельный вход по заголовку `X-Test-Token`. Он открывает только двух тестовых пользователей (см. [Тестовые данные](#тестовые-данные)).

**Устойчивость к сбоям ИИ.** Если YandexGPT недоступен или не настроен, приложение продолжает работать: карта строится по правилам, методика берётся из шаблона, подбор возвращает кандидатов без оценки. У запросов к ИИ есть таймаут 20 с, один повтор, не больше 3 параллельных обращений и кэш на 1 час.

## Запуск одной командой

Нужны Docker и Docker Compose v2.

```bash
git clone https://github.com/nayrest/sobra-max.git
cd sobra-max
cp .env.example .env          # Windows PowerShell: Copy-Item .env.example .env
# заполнить .env (см. «Переменные окружения»)

docker compose --profile local up -d --build
```

Эта команда поднимает все локальные компоненты: бота и API (`startup-discovery`), базу (`postgres`) и мини-приложение (`web`, http://localhost:8080). Схема БД создаётся автоматически при старте. Сборка занимает 1–2 минуты без учёта загрузки базовых образов.

На сервере фронтенд раздаёт системный Nginx с HTTPS, поэтому там запуск без профиля: `docker compose up -d --build`.

Проверка:

```bash
curl http://localhost:3000/api/health          # {"status":"ok"}
docker compose logs --tail=20 startup-discovery
```

В логах должно быть:

```text
💾 PostgreSQL: схема проверена/создана
🤖 AI Matching: YandexGPT подключён
🚀 Бот SOBRA запускается
🌐 API для мини-приложения слушает порт 3000
```

**Мини-приложение в обычном браузере.** Вне MAX у приложения нет подписи `initData`, поэтому для локальной проверки есть режим отладки:
1. В `.env` поставить `API_DEBUG_AUTH=true` и перезапустить: `docker compose --profile local up -d`.
2. Открыть http://localhost:8080/?debug_user=1001. Число — любой id пользователя, второй аккаунт — `?debug_user=1002`.

На сервере для сдачи `API_DEBUG_AUTH` всегда `false`.

## Переменные окружения

Файл `.env` в корне проекта. Шаблон — `.env.example`. Файл `.env` не хранится в Git и исключён из Docker-образа через `.dockerignore`.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота MAX. Нужен для бота, уведомлений и проверки подписи `initData` |
| `POSTGRES_DB` | да | Имя базы, например `startup_discovery` |
| `POSTGRES_USER` | да | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | да | Пароль PostgreSQL (любой, база не публикуется наружу) |
| `YANDEX_API_KEY` | да, для ИИ-функций | API-ключ сервисного аккаунта Yandex Cloud с ролью `ai.languageModels.user`. Нужен для Idea Check, методики задач и AI Match. Без него приложение запускается в запасном режиме: карта по правилам, подбор без оценки ИИ |
| `YANDEX_FOLDER_ID` | да, для ИИ-функций | id каталога Yandex Cloud, в котором создан сервисный аккаунт |
| `API_DEBUG_AUTH` | нет | `true` — вход по `?debug_user=N` без MAX. Только для локальной отладки, по умолчанию `false` |
| `API_TEST_TOKEN_FOUNDER` | нет | Токен тестового основателя для автоматической проверки (`openssl rand -hex 24`, не короче 24 символов) |
| `API_TEST_TOKEN_CANDIDATE` | нет | Токен тестового кандидата |

`DATABASE_URL`, `API_PORT=3000` и путь к сертификату (`NODE_EXTRA_CA_CERTS`) задаются в `docker-compose.yml` и настройки не требуют.

## Порты

| Порт | Сервис | Доступ |
|---|---|---|
| `3000` | API (`startup-discovery`) | Только `127.0.0.1`, наружу — через Nginx |
| `8080` | Мини-приложение (`web`, профиль `local`) | Только `127.0.0.1` |

## Работа с данными

Все данные хранятся в PostgreSQL, в томе `postgres_data`, поэтому они переживают перезапуск контейнеров. Схема (`backend/schema.sql`) применяется при каждом старте: таблицы и колонки создаются, если их ещё нет, существующие данные не меняются.

| Таблица | Что хранит |
|---|---|
| `users` | id и имя пользователя MAX (из подписанных данных) |
| `startups` | Проект: ответы Idea Check, карта (`idea_map`, JSONB), готовность, статус черновик/опубликован |
| `action_tasks` | Задачи плана действий: методика, результат, статус блока и готовность «было → стало» |
| `search_profiles` | Профиль: цель, «о себе», ФИО, телефон, e-mail, согласие на показ контактов, фото |
| `offers` | Отклики кандидатов и решение основателя |
| `invites` | Приглашения кандидатов основателем |

**Персональные данные.**
- ФИО, телефон и e-mail сохраняются только с согласия пользователя (время согласия записывается в `contacts_consent_at`).
- До MATCH этих данных не видит никто. В подборе основатель видит только имя из MAX, текст «о себе» и фото.
- Телефон приводится к виду `+7XXXXXXXXXX`.
- Фото обрезается в браузере до 256×256 и сжимается в JPEG, при этом удаляются EXIF и геометки. Сервер проверяет сигнатуру файла и размер (не больше 200 КБ). Отдаётся фото по ссылке со случайным 128-битным токеном.

**Резервная копия и восстановление:**

```bash
docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backup.sql
docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < backup.sql
```

## Тестовые данные

**Демо-данные** (`demo-data.sql`) — 7 вымышленных проектов и 6 кандидатов, среди них один заведомо нерелевантный. На них видно, как работают поиск и AI Match. Id демо-пользователей: 900000000001–900000000199. В MAX таких пользователей нет, поэтому отклик на демо-проект сохраняется, а уведомление не доставляется. Так и задумано.

**Тестовые учётные записи** (`test-data.sql`) — для автоматической проверки API:

| Роль | id | Вход |
|---|---|---|
| Основатель | 910000000001 | заголовок `X-Test-Token: <API_TEST_TOKEN_FOUNDER>` |
| Кандидат | 910000000002 | заголовок `X-Test-Token: <API_TEST_TOKEN_CANDIDATE>` |

Проекты и профили тестовых пользователей изолированы: реальные пользователи их не видят, тестовые не видят реальных.

Загрузка (повторный запуск безопасен):

```bash
docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < demo-data.sql
docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < test-data.sql
```

Каждый прогон проверок создаёт новый тестовый проект. Команды очистки есть в конце `test-data.sql`.

## Пошаговая проверка

### В MAX (основной сценарий)

1. Открыть https://max.ru/t558_hakaton_max_bot → «Начать» (бот пришлёт инструкцию) → открыть мини-приложение кнопкой в чате с ботом.
2. Заполнить профиль и отметить согласие → «Сохранить профиль».
3. «Проекты» → «+ Проверить новую идею» → заполнить поля со звёздочкой. Для примера в «Как проверяли спрос?» можно написать «Думаю, спрос будет». → «Сформировать карту проекта».
4. Посмотреть карту: статусы блоков, готовность, линейку из 5 шагов.
5. «Следующие шаги» → задача «Проверить спрос» → «Как это сделать» → «✨ Попросить ИИ расписать под мой проект».
6. «Внести результат» → например, «Лендинг посетили 300 человек, 24 оставили заявку» → «Обновить карту». Блок станет ✓, готовность вырастет, запись появится в «Истории обновлений».
7. «Опубликовать» → «Подобрать партнёра» → кандидаты с оценкой ИИ → «Пригласить в проект».
8. Со второго аккаунта MAX: профиль → «Поиск» → «Найти проекты» → «Откликнуться».
9. С первого аккаунта: «Отклики» → «Принять» → MATCH. У обоих во вкладке «Контакты» появятся телефон и e-mail.

Если второго аккаунта нет, отклик можно проверить на демо-проектах: они видны в поиске с целью «Войти в команду» или «Партнёрство».

### Автоматически (API)

```bash
python3 scripts/check_api.py DATA-API.yaml --env .env
# локально:
python3 scripts/check_api.py DATA-API.yaml --env .env --base-url http://localhost:3000/api
```

Ожидаемый результат — `Итого: 23 из 23 обязательных проверок прошли.` Скрипт по очереди проходит весь сценарий от имени тестовых пользователей и проверяет коды ответов и обязательные поля. Негативные случаи тоже проверяются: запрос без авторизации, профиль без согласия, чужой проект, повторный Update, чужое принятие отклика.

## Ожидаемое поведение

| Действие | Результат |
|---|---|
| Ответ без фактов («думаю, спрос будет») | Блок — «Гипотеза» ~ |
| Пустой ответ | Блок — «Не проработано» ✗, в плане появляется задача |
| Результат с цифрами и фактами (интервью, заявки, продажи) | Блок — «Подтверждено» ✓, задача закрыта, готовность растёт |
| Результат без фактов | Блок остаётся гипотезой, в плане появляется следующий шаг по нему |
| Кандидат с опытом по теме проекта | Высокий процент, «почему подходит», «что уточнить» |
| Нерелевантный кандидат | Низкий процент или «слабое соответствие» |
| Профиль без согласия | Не сохраняется, приложение подсказывает отметить согласие |
| Отклик принят | Бот уведомляет кандидата, контакты видны обеим сторонам |

| Экран шире 900 px | Меню сбоку (выезжает по ☰, от 1200 px закреплено), контент на всю ширину |

Примеры запросов и ответов API — в [`openapi.yaml`](openapi.yaml). Удобно смотреть в https://editor.swagger.io.

## Остановка и повторный запуск

```bash
docker compose --profile local down        # остановить (данные в томе сохраняются)
docker compose --profile local up -d       # запустить снова
docker compose --profile local up -d --build   # пересобрать после изменений кода
docker compose logs -f startup-discovery   # логи бота и API

docker compose --profile local down -v     # остановить и УДАЛИТЬ базу (полный сброс)
```

На сервере те же команды без `--profile local`. Контейнеры запущены с `restart: unless-stopped` и поднимаются сами после перезагрузки сервера.

## Развёртывание на сервере

Рабочая версия — ВМ в Yandex Cloud, проект в `/var/www/sobra`.

1. Установить Docker, Nginx и certbot. Получить сертификат для `<ip-с-дефисами>.nip.io`.
2. Nginx: корень сайта — папка `frontend/`, блок `/api/` — из `deploy/nginx-api-location.conf`.
3. `.env` заполнить по таблице выше, `API_DEBUG_AUTH=false`.
4. `docker compose up -d --build`, затем загрузить `demo-data.sql` и `test-data.sql`.
5. В настройках бота на платформе MAX указать адрес мини-приложения `https://<ip-с-дефисами>.nip.io/`.

Обновление:

```bash
cd /var/www/sobra
git pull
docker compose up -d --build
python3 scripts/check_api.py DATA-API.yaml --env .env
```

## Известные ограничения

- **Мини-приложение работает только из MAX** по публичному HTTPS-адресу. Локально его можно открыть только в режиме отладки (`API_DEBUG_AUTH=true`).
- **Уведомления бота** приходят только тем, кто хотя бы раз нажал «Старт» в чате с ботом. Это ограничение MAX. Демо- и тестовым пользователям уведомления не доставляются, запись в базе при этом создаётся.
- **ИИ оценивает текст, а не проверяет факты.** Если основатель впишет выдуманные цифры, блок будет засчитан. SOBRA фиксирует, что заявлено, а не проверяет это.
- **Без ключа YandexGPT** карта строится по простым правилам: цифры плюс слова «интервью», «заявки», «продажи» и т. п. Подбор идёт по фильтрам без объяснений.
- **ИИ-оценка в поиске** даётся для первых 8 проектов, остальные показываются без неё. Ответ ИИ занимает 2–10 секунд.
- **Переписки внутри SOBRA нет.** После MATCH стороны связываются по телефону, e-mail или в MAX.
- **Один проект — один тип поиска** (команда или партнёрство).
- **Инвестиции, вакансии и пилоты** в MVP сознательно не входят.
