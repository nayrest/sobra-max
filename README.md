# SOBRA — поиск партнёра под бизнес-идею в MAX

SOBRA — мини-приложение и бот в мессенджере MAX для начинающих предпринимателей. Оно показывает, что в бизнес-идее уже подтверждено, а что нет, и помогает найти партнёра или co-founder'а.

SOBRA не оценивает, хорошая ли идея. Она показывает, что нужно проверить, фиксирует прогресс и помогает найти человека с недостающими компетенциями.

## Назначение

**Проблема.** Человек с бизнес-идеей обычно не знает, что в ней уже подтверждено, а что пока только предположение. Партнёра он ищет по знакомым и в чатах, объясняет каждому идею заново и не может коротко сформулировать, какие навыки ему нужны.

**Решение.** SOBRA проводит основателя по циклу из пяти шагов:

| Шаг | Что происходит |
|---|---|
| 1. **Idea Check** | Основатель отвечает на вопросы: клиент, проблема, решение, конкуренты, спрос, бизнес-модель, экономика, какой партнёр нужен |
| 2. **Project Map** | ИИ раскладывает ответы по 7 блокам: ✓ подтверждено фактами, ~ гипотеза, ✗ не проработано. Считается готовность проекта в процентах |
| 3. **Action Plan** | По каждому неподтверждённому блоку появляется задача («Провести интервью», «Проверить спрос»…) с методикой; ИИ может расписать её под конкретный проект |
| 4. **Update** | Основатель возвращается с результатом, карта пересчитывается: блок меняется с ✗ на ✓, готовность растёт. Если фактов мало, по блоку появляется следующий шаг |
| 5. **AI Match** | ИИ сравнивает потребность проекта с опытом кандидатов по смыслу и объясняет: почему подходит, чего не хватает, что уточнить |

Кандидат заполняет профиль, ищет проекты (ИИ объясняет, насколько он подходит) и откликается. Когда основатель принимает отклик, случается **MATCH**: стороны видят телефон и e-mail друг друга, а кнопка «Написать в MAX» открывает профиль собеседника в MAX, чтобы начать переписку. Контакты показываются только при согласии пользователя.

**Целевая аудитория:**
- основатели на ранней стадии (от идеи до первых продаж), которым нужен co-founder или партнёр;
- специалисты, которые хотят войти в команду или стать партнёром в проекте.

## Основной пользовательский сценарий

**Основатель**
1. Открывает бота в MAX и запускает мини-приложение. Профиль на входе не нужен — сразу открываются проекты.
2. «Проекты» → «Проверить новую идею» → отвечает на вопросы и получает карту проекта.
3. В «Следующих шагах» выбирает задачу, выполняет её и нажимает «Внести результат». Карта пересчитывается.
4. «Опубликовать» — только теперь приложение просит профиль: ФИО, e-mail, телефон, цель («Развиваю свою идею») и согласие на показ контактов после MATCH. После сохранения возвращает к проекту.
5. «Подобрать партнёра»: ИИ показывает кандидатов с объяснением → «Пригласить в проект».
6. «Отклики» → «Принять» → MATCH. Во вкладке «Контакты» — телефон, e-mail и кнопка «Написать в MAX».

**Кандидат**
1. «Поиск» → выбирает цель и сферу → ИИ оценивает каждый проект (точнее, если в профиле заполнено «О себе»).
2. «Откликнуться» — приложение просит заполнить профиль, если его ещё нет, и возвращает к отклику → сообщение основателю.
3. Чтобы основатели сами находили его, отмечает в профиле «Показывать мой профиль основателям».
4. Бот присылает уведомление о решении. После MATCH контакты основателя появляются во вкладке «Контакты».

Бот в чате только знакомит с сервисом (`/start`) и присылает уведомления: новый отклик, приглашение, MATCH, отказ. Вся работа идёт в мини-приложении.

## Состав и архитектура

```text
 Пользователь в MAX
   │  чат с ботом                         мини-приложение (WebView)
   ▼                                        │  HTTPS, Authorization: Bearer <initData>
 MAX Bot API ◄──── long polling ────┐       ▼
                                    │   Nginx (HTTPS, Let's Encrypt)
                                    │     ├── /       → frontend/ (статика)
                                    │     └── /api/   → 127.0.0.1:3000
                                    │                    │
                         ┌──────────┴────────────────────▼──────────┐
                         │ контейнер startup-discovery (Node.js 24) │
                         │  index.js       — бот: /start, уведомления│
                         │  api.js         — REST API (Express 5)    │
                         │  idea-check.js  — карта проекта           │
                         │  action-plan.js — план действий, Update   │
                         │  ai-matching.js — AI Match (YandexGPT)    │
                         │  db.js          — доступ к PostgreSQL     │
                         └──────────┬───────────────────┬───────────┘
                                    ▼                   ▼
                          контейнер postgres      YandexGPT API
                          (PostgreSQL 17)         (Yandex Cloud)
```

| Компонент | Где | Назначение |
|---|---|---|
| `backend/` | контейнер `startup-discovery` | Бот и REST API в одном процессе Node.js |
| `frontend/` | Nginx на сервере / контейнер `web` локально | Мини-приложение: HTML, CSS, JavaScript без сборки |
| PostgreSQL 17 | контейнер `postgres` | Пользователи, проекты, карты, задачи, профили, отклики, фото |
| YandexGPT | внешний сервис | Карта проекта, методика задач, AI Match |

**Авторизация.** Мини-приложение передаёт `initData` от MAX Bridge. Сервер проверяет подпись по алгоритму MAX: HMAC-SHA256, ключ получается из токена бота. Срок действия подписи — 24 часа. Имя и id пользователя берутся только из подписанных данных, подделать их нельзя. Для автоматической проверки есть отдельный вход по заголовку `X-Test-Token`. Он открывает только двух тестовых пользователей (см. [Тестовые данные](#тестовые-данные)).

**Устойчивость к сбоям ИИ.** Если YandexGPT недоступен или не настроен, приложение продолжает работать: карта строится по правилам, методика берётся из шаблона, подбор возвращает кандидатов без оценки. Каждый запрос к ИИ ограничен таймаутом 20 с и повторяется один раз. Одновременно идёт не больше 3 обращений, а оценки подбора кэшируются на 1 час.

## Возможности MAX

SOBRA целиком живёт внутри MAX: от первого запуска до разговора с найденным партнёром.

| Возможность MAX | Где в SOBRA | Что даёт пользователю |
|---|---|---|
| Бот и уведомления (MAX Bot API) | Сообщения о новом отклике, приглашении, MATCH и отказе | Не нужно заходить в приложение, чтобы узнать новости |
| Мини-приложение и подписанные данные пользователя (`initData`) | Вход без логина и пароля | Регистрация в один тап, чужой аккаунт не подделать |
| **Запрос номера телефона** (`WebApp.requestContact`) | Профиль → «✓ Подтвердить номер через MAX» | Номер, привязанный к аккаунту MAX, без ручного ввода. Значок «✓ Телефон подтверждён» в подборе, откликах и контактах защищает от фейков |
| **Переход в чат** (`WebApp.openMaxLink`) | «Контакты» → «💬 Написать в MAX» после MATCH | Сразу начать разговор с партнёром, не выходя из MAX. Ссылка строится из ника MAX, а без ника — из приглашения, которое человек пересылает боту (профиль MAX → «Пригласить в друзья» → «Поделиться» → чат с ботом). Бот сохраняет ссылку сам |

Как проверить:
1. «Профиль» → «✓ Подтвердить номер через MAX» → разрешить в MAX. Рядом с телефоном появится «✓ Подтверждён через MAX».
2. Пройти сценарий до MATCH (раздел [Пошаговая проверка](#пошаговая-проверка)) → «Контакты» → «💬 Написать в MAX» → откроется профиль собеседника в MAX.

## Запуск одной командой

Все локальные компоненты (бот и API, база данных, мини-приложение) запускаются одной командой из корня репозитория:

```bash
docker compose --profile local up -d --build
```

Нужны Docker и Docker Compose v2 (на Windows и macOS — Docker Desktop). Для автоматических проверок из шага 7 дополнительно нужен Python 3. Ниже — полный порядок с первого запуска.

**Разница между ОС.** Все команды `docker compose ...` одинаковые в Linux, macOS и Windows. Отличаются только вспомогательные:

| Действие | Linux / macOS (и Git Bash в Windows) | Windows PowerShell |
|---|---|---|
| Создать `.env` | `cp .env.example .env` | `Copy-Item .env.example .env` |
| Сгенерировать тестовый токен | `python3 -c "import secrets; print(secrets.token_hex(24))"` | `python -c "import secrets; print(secrets.token_hex(24))"` |
| Загрузить SQL-файл в базу | через `<` (шаг 4) | через `docker compose cp` (шаг 4) |
| Запрос к API | `curl` | `curl.exe` (просто `curl` в PowerShell — другая команда) |
| Запустить скрипт проверки | `python3 scripts/check_api.py ...` | `python scripts\check_api.py ...` |

**1. Получить код**

```bash
git clone https://github.com/nayrest/sobra-max.git
cd sobra-max
```

**2. Создать `.env`**

```bash
cp .env.example .env          # Windows PowerShell: Copy-Item .env.example .env
```

Заполнить в `.env`:
- `BOT_TOKEN` — токен бота MAX;
- `POSTGRES_PASSWORD` — любой пароль;
- `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` — для ИИ-функций;
- `API_DEBUG_AUTH=true` — чтобы открыть мини-приложение в обычном браузере;
- `API_TEST_TOKEN_FOUNDER` и `API_TEST_TOKEN_CANDIDATE` — любые строки от 24 символов, для автоматических проверок. Сгенерировать: `python3 -c "import secrets; print(secrets.token_hex(24))"` (в Windows — `python` вместо `python3`).

> **Важно про токен бота.** MAX отдаёт сообщения бота только одному получателю. Если запустить проект локально с тем же `BOT_TOKEN`, что и у рабочей версии на сервере, два экземпляра будут забирать сообщения друг у друга. Для локальной проверки лучше использовать токен отдельного тестового бота. API, база и мини-приложение от этого не зависят.

**3. Запустить**

```bash
docker compose --profile local up -d --build
```

Поднимаются три контейнера: `startup-discovery` (бот и API, http://localhost:3000), `postgres` (база) и `web` (мини-приложение, http://localhost:8080). Схема БД создаётся автоматически. Сборка занимает меньше минуты без учёта загрузки базовых образов.

**4. Загрузить демо-данные и тестовых пользователей**

```bash
docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < demo-data.sql
docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < test-data.sql
```

В PowerShell перенаправление `<` не работает. Там файлы копируются в контейнер и выполняются внутри, так кириллица не портится:

```powershell
docker compose cp demo-data.sql postgres:/tmp/demo-data.sql
docker compose cp test-data.sql postgres:/tmp/test-data.sql
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -f /tmp/demo-data.sql -f /tmp/test-data.sql'
```

**5. Проверить, что всё работает**

```bash
curl http://localhost:3000/api/health          # {"status":"ok"}; в PowerShell: curl.exe ...
docker compose logs --tail=20 startup-discovery
```

В логах должно быть:

```text
💾 PostgreSQL: схема проверена/создана
🤖 AI Matching: YandexGPT подключён
🚀 Бот SOBRA запускается
🌐 API для мини-приложения слушает порт 3000
```

**6. Открыть мини-приложение**

http://localhost:8080/?debug_user=1001 — вход от имени пользователя с id 1001. Второй пользователь, например для отклика и MATCH: http://localhost:8080/?debug_user=1002. Режим работает только при `API_DEBUG_AUTH=true`. В MAX вход идёт по подписи `initData`, и этот режим не нужен.

**7. Прогнать автоматические проверки API**

```bash
python3 scripts/check_api.py DATA-API.yaml --env .env --base-url http://localhost:3000/api
```

Нужен Python 3 с PyYAML (`pip install pyyaml`), на Windows команда `python` вместо `python3`. Ожидаемый результат: `Итого: 23 из 23 обязательных проверок прошли.`

Остановка и повторный запуск описаны в разделе [Остановка и повторный запуск](#остановка-и-повторный-запуск).

### Готовый образ в Docker Hub (необязательно)

Образ backend (API и бот) опубликован в Docker Hub: https://hub.docker.com/r/nayrest/sobra-backend

```bash
docker pull nayrest/sobra-backend:latest
```

Тег `latest` — актуальная версия. По умолчанию `docker compose` собирает образ из исходников, и Docker Hub не нужен. Чтобы вместо сборки взять готовый образ, в `docker-compose.yml` у сервиса `startup-discovery` замените строку `build: ./backend` на `image: nayrest/sobra-backend:latest` и запускайте без `--build`:

```bash
docker compose --profile local up -d
```

В образе только backend. Репозиторий всё равно нужен: мини-приложение (`frontend/`), `docker-compose.yml`, `.env`, демо- и тестовые данные берутся из него. Секретов в образе нет — `.env` исключён через `backend/.dockerignore`.

Обновление образа после изменений в коде (для команды):

```bash
docker compose build startup-discovery
docker tag startup-discovery-max-startup-discovery nayrest/sobra-backend:latest
docker push nayrest/sobra-backend:latest
```

Имя собранного образа зависит от папки проекта — посмотрите его командой `docker images`.

## Переменные окружения

Файл `.env` в корне проекта. Шаблон — `.env.example`. Файл `.env` не хранится в Git и исключён из Docker-образа через `.dockerignore`.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота MAX. Нужен для бота, уведомлений и проверки подписи `initData` |
| `POSTGRES_DB` | да | Имя базы, например `startup_discovery` |
| `POSTGRES_USER` | да | Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | да | Пароль PostgreSQL (любой, база не публикуется наружу) |
| `YANDEX_API_KEY` | да, для ИИ-функций | API-ключ сервисного аккаунта Yandex Cloud с ролью `ai.languageModels.user`. Нужен для Idea Check, методики задач и AI Match. Без него приложение запускается в запасном режиме: карта по правилам, подбор без оценки ИИ |
| `YANDEX_FOLDER_ID` | да, для ИИ-функций | id каталога Yandex Cloud, в котором создан сервисный аккаунт |
| `API_DEBUG_AUTH` | нет | `true` — вход по `?debug_user=N` без MAX. Только для локальной отладки, по умолчанию `false` |
| `API_TEST_TOKEN_FOUNDER` | нет | Токен тестового основателя для автоматической проверки, не короче 24 символов (генерация — в разделе запуска) |
| `API_TEST_TOKEN_CANDIDATE` | нет | Токен тестового кандидата |

`DATABASE_URL`, `API_PORT=3000` и путь к сертификату (`NODE_EXTRA_CA_CERTS`) задаются в `docker-compose.yml` и настройки не требуют.

## Порты

| Порт | Сервис | Доступ |
|---|---|---|
| `3000` | API (`startup-discovery`) | Только `127.0.0.1`, наружу — через Nginx |
| `8080` | Мини-приложение (`web`, профиль `local`) | Только `127.0.0.1` |
| `5432` | PostgreSQL | Только внутри сети Docker, не публикуется |
| `443` | Nginx на сервере (HTTPS) | Публичный: мини-приложение и `/api/` |

Бот получает обновления от MAX через long polling, входящий порт ему не нужен.

События в реальном времени (`/api/events`) идут через тот же Nginx: сервер отвечает заголовком `X-Accel-Buffering: no` и раз в 20 секунд шлёт `ping`, поэтому отдельная настройка Nginx не нужна (достаточно `proxy_read_timeout` больше 20 секунд — в `deploy/nginx-api-location.conf` стоит 30).

## Работа с данными

Все данные хранятся в PostgreSQL, в томе `postgres_data`, поэтому они переживают перезапуск контейнеров. Схема (`backend/schema.sql`) применяется при каждом старте: таблицы и колонки создаются, если их ещё нет, существующие данные не меняются.

| Таблица | Что хранит |
|---|---|
| `users` | id, имя и ник пользователя MAX (из подписанных данных) |
| `startups` | Проект: ответы Idea Check, карта (`idea_map`, JSONB), готовность, статус: черновик / опубликован / удалён. Черновик удаляется полностью; опубликованный проект при удалении скрывается из поиска и подбора, ожидающие отклики отклоняются, а случившиеся MATCH и контакты сохраняются |
| `action_tasks` | Задачи плана действий: методика, результат, статус блока и готовность «было → стало» |
| `search_profiles` | Профиль: цель, «о себе», ФИО, телефон, e-mail, ссылка на профиль MAX, согласие на показ контактов, фото |
| `ai_match_log` | Журнал оценок AI Match (проект, кандидат, процент) — для статистики |
| `reports` | Жалобы пользователей на проекты и людей |
| `contact_clicks` | Нажатия «Написать в MAX», на телефон и e-mail после MATCH — для статистики |
| `offers` | Отклики кандидатов и решение основателя |
| `invites` | Приглашения кандидатов основателем |

**Персональные данные.**
- ФИО, телефон, e-mail и ссылка на профиль MAX сохраняются только с согласия пользователя (время согласия записывается в `contacts_consent_at`).
- Кнопка «Написать в MAX» ведёт на `https://max.ru/<ник>` (ник приходит в подписанных данных MAX) или на ссылку-приглашение `https://max.ru/u/…`. Её нельзя получить через API, поэтому человек пересылает боту приглашение из своего профиля, и бот сохраняет ссылку сам; вставить её вручную тоже можно. Внутри MAX кнопка открывается через `WebApp.openMaxLink`.
- До MATCH этих данных не видит никто. В подборе основатель видит только имя из MAX, текст «о себе» и фото.
- Телефон приводится к виду `+7XXXXXXXXXX`.
- Фото обрезается в браузере до 256×256 и сжимается в JPEG, при этом удаляются EXIF и геометки. Сервер проверяет сигнатуру файла и размер (не больше 200 КБ). Отдаётся фото по ссылке со случайным 128-битным токеном.

**Статистика использования.**
- Для оценки продукта сервер учитывает действия: оценки ИИ (`ai_match_log`), нажатия на контакты после MATCH (`contact_clicks`), жалобы (`reports`). Хранится только id пользователя MAX, действие и время. Переписка в MAX не видна и не хранится.
- Пользователь предупреждён об этом в профиле, рядом с согласием на показ контактов.
- Отчёт — только общие числа: запрос к базе на сервере, метода API для статистики нет. Демо- и тестовые учётные записи не учитываются:
  ```bash
  docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < scripts/stats.sql
  ```
  Показывает регистрации, заполненные профили, проекты, AI-мэтчи, MATCH, нажатия «Написать в MAX» и жалобы.

Команды ниже одинаковые для Linux, macOS и Windows: файл создаётся внутри контейнера и копируется через `docker compose cp`, поэтому кодировка не портится.

**Резервная копия:**

```bash
docker compose exec postgres sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > /tmp/backup.sql'
docker compose cp postgres:/tmp/backup.sql backup.sql
```

**Восстановление** — только в пустую базу, иначе появятся ошибки «already exists». Копия загружается до запуска приложения, чтобы схема не создалась раньше:

```bash
docker compose down -v                  # удалить текущую базу
docker compose up -d postgres           # поднять только PostgreSQL
docker compose cp backup.sql postgres:/tmp/backup.sql
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -f /tmp/backup.sql'
docker compose up -d                    # запустить остальное
```

## Безопасность и защита от мошенников

SOBRA рассчитана на начинающих предпринимателей, поэтому защита от мошенников заложена в продукт:

| Мера | Как работает |
|---|---|
| **Вход только через MAX** | Каждый запрос подписан MAX, подпись проверяется на сервере. Войти под чужим аккаунтом нельзя, анонимных аккаунтов нет: аккаунт MAX привязан к номеру телефона |
| **Подтверждённый телефон** | Кнопка «Подтвердить номер через MAX» в профиле (`WebApp.requestContact`). MAX подписывает номер, привязанный к аккаунту, сервер проверяет подпись ключом бота. Рядом с человеком появляется значок «✓ Телефон подтверждён». Если вписать другой номер вручную, отметка снимается |
| **Данные — только когда нужны** | Профиль с контактами не спрашивается на входе: Idea Check, карта, план и поиск работают без него. ФИО, телефон, e-mail и согласие приложение просит только перед публикацией проекта или откликом — без них не случится MATCH. Сервер проверяет это сам (ответ 409 `profile_required`) |
| **Контакты только после MATCH** | До MATCH основатель видит только имя из MAX, «о себе» и фото. Телефон, e-mail и ссылка на MAX открываются после того, как основатель принял отклик, и только с согласия человека. Приглашение от основателя контактов не открывает: MATCH начинается с отклика кандидата |
| **Предупреждение** | В «Откликах» и «Контактах»: SOBRA не берёт денег за знакомство, не переводите деньги «за вход в команду» и не сообщайте коды из SMS |
| **Жалобы** | «⚑ Пожаловаться» на проект или человека (просит деньги, фейк, спам, оскорбления). Жалобы анонимны. После жалоб от 3 разных людей проект или человек скрывается из поиска, подбора и приглашений до проверки |
| **Суточные лимиты** | Не больше 10 проектов, 20 откликов, 30 приглашений, 50 решений по откликам и 20 жалоб в сутки на человека (ответ 429). Так нельзя массово собирать контакты или рассылать спам |
| **Изоляция данных** | Чужой проект — 404, чужой отклик — 403. Это проверяется автоматически в `DATA-API.yaml` |
| **Инфраструктура** | База не публикуется наружу, API только через HTTPS и Nginx, режим отладки выключен, ссылки на фото со случайным токеном, `.env` не попадает в Git и образ |

Жалобы видны администратору в логах (`⚑ Жалоба #…`) и в таблице `reports`.

## Пошаговая проверка

### В MAX (основной сценарий)

1. Открыть https://max.ru/t558_hakaton_max_bot → «Начать» (бот пришлёт инструкцию) → открыть мини-приложение кнопкой в чате с ботом.
2. Профиль сразу заполнять не нужно: приложение попросит его при публикации проекта или отклике.
3. «Проекты» → «+ Проверить новую идею» → заполнить поля со звёздочкой. Для примера в «Как проверяли спрос?» можно написать «Думаю, спрос будет». → «Сформировать карту проекта».
4. Посмотреть карту: статусы блоков, готовность, линейку из 5 шагов.
5. «Следующие шаги» → задача «Проверить спрос» → «Как это сделать» → «✨ Попросить ИИ расписать под мой проект».
6. «Внести результат» → например, «Лендинг посетили 300 человек, 24 оставили заявку» → «Обновить карту». Блок станет ✓, готовность вырастет, запись появится в «Истории обновлений».
7. «Опубликовать» → «Подобрать партнёра» → кандидаты с оценкой ИИ → «Пригласить в проект».
8. Со второго аккаунта MAX: профиль → «Поиск» → «Найти проекты» → «Откликнуться».
9. С первого аккаунта: «Отклики» → «Принять» → MATCH. У обоих во вкладке «Контакты» появятся телефон и e-mail.

Если второго аккаунта нет:
- откликнитесь на проект с меткой «Демо» — через несколько секунд демо-основатель примет отклик, и во вкладке «Контакты» появится MATCH;
- или пригласите демо-кандидата из «Подобрать партнёра» — через несколько секунд его отклик придёт в «Отклики», его можно принять;
- весь путь до MATCH и обмена контактами проходит автоматическая проверка ниже (роли основателя и кандидата);
- локально второй пользователь открывается по ссылке `?debug_user=1002` (шаг 6 раздела [Запуск одной командой](#запуск-одной-командой)).

### Автоматически (API)

```bash
python3 scripts/check_api.py DATA-API.yaml --env .env
# локально:
python3 scripts/check_api.py DATA-API.yaml --env .env --base-url http://localhost:3000/api
```

Ожидаемый результат — `Итого: 23 из 23 обязательных проверок прошли.` Скрипт по очереди проходит весь сценарий от имени тестовых пользователей и проверяет коды ответов и обязательные поля. Негативные случаи тоже проверяются: запрос без авторизации, профиль без согласия, чужой проект, повторный Update, чужое принятие отклика.

## Развёртывание на сервере

Этот раздел описывает рабочую версию, которая открывается в MAX. Для локальной проверки он не нужен, достаточно раздела [Запуск одной командой](#запуск-одной-командой).

Отличия сервера от локального запуска:
- мини-приложение раздаёт системный Nginx по HTTPS, поэтому сервис `web` не запускается (команды без `--profile local`);
- `API_DEBUG_AUTH=false`, вход только через MAX и тестовые токены.

Рабочая версия — ВМ в Yandex Cloud, проект в `/var/www/sobra`.

1. Установить Docker, Nginx и certbot. Получить сертификат для `<ip-с-дефисами>.nip.io`.
2. Nginx: корень сайта — папка `frontend/`, блок `/api/` — из `deploy/nginx-api-location.conf`.
3. `.env` заполнить по таблице выше, `API_DEBUG_AUTH=false`.
4. `docker compose up -d --build`, затем загрузить `demo-data.sql` и `test-data.sql`.
5. В настройках бота на платформе MAX указать адрес мини-приложения `https://<ip-с-дефисами>.nip.io/`.

Обновление:

```bash
cd /var/www/sobra
git pull
docker compose up -d --build
python3 scripts/check_api.py DATA-API.yaml --env .env
```

## Известные ограничения

- **Мини-приложение работает только из MAX** по публичному HTTPS-адресу. Локально его можно открыть только в режиме отладки (`API_DEBUG_AUTH=true`). Этот режим пускает под любым id без проверки, поэтому на сервере он выключен.
- **Один токен бота — один запущенный экземпляр.** Если запустить проект локально с токеном рабочего бота, локальная и серверная копии будут делить сообщения. Для локального запуска лучше использовать отдельного тестового бота.
- **Уведомления бота** приходят только тем, кто хотя бы раз нажал «Начать» в чате с ботом. Это ограничение MAX. Демо- и тестовым пользователям уведомления не доставляются, запись в базе при этом создаётся.
- **ИИ оценивает текст, а не проверяет факты.** Если основатель впишет выдуманные цифры, блок будет засчитан. SOBRA фиксирует, что заявлено, а не проверяет это.
- **Без ключа YandexGPT** карта строится по простым правилам: цифры плюс слова «интервью», «заявки», «продажи» и т. п. Подбор идёт по фильтрам без объяснений.
- **ИИ-оценка в поиске** даётся для первых 8 проектов, остальные показываются без неё. Ответ ИИ занимает 2–10 секунд.
- **Переписки внутри SOBRA нет.** После MATCH стороны связываются в MAX (кнопка «Написать в MAX»), по телефону или e-mail. Открыть чат по одному id пользователя MAX нельзя, поэтому кнопка появляется, только если у человека есть ник в MAX или он переслал боту ссылку на свой профиль.
- **Один проект — один тип поиска** (команда или партнёрство).
- **Подтверждается телефон, а не личность.** ФИО человек вводит сам. Проверка паспорта (например, через Госуслуги) в MVP не входит. Скрытые после жалоб проекты администратор пока разбирает вручную, через базу.
- **Инвестиции, вакансии и пилоты** в MVP сознательно не входят.
